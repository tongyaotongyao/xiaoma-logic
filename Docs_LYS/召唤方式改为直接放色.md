# 召唤方式默认改为「直接放当前色」

> 对应问题：轮盘选色是伪选择。相关设计见 `ADVENTURE_DESIGN.md` §3.1（只读参考，未修改）。

## 问题

每格的色区在关卡数据 `Regions` 里是固定的，放置时颜色不符会被直接拒绝（`OnWheelSelectColour` 里的
`Level->Regions[Idx] != ColourIndex` 分支）。也就是说，站在格子上时**只有一种颜色放得上去**，
轮盘里其余 5 个扇区全是必然失败的选项。

轮盘因此不提供任何决策空间，只增加一次「点错 → 小马摇头 → 重来」的操作。原设计的意图是
「轮盘只增加操作感，不增加惩罚」，但当惩罚客观存在（多点一次、还要听错误音效）时，操作感就变成了摩擦。

## 改法（方案 A）

把默认召唤方式改成 `EXiaomaSummonMode::DirectRegion`：站到格子上按召唤键，直接放该格颜色的小马；
格子上已有小马时，同一个键表示「请回」。轮盘仍保留在设置里，想用的人可以自己切回去。

`InteractPressed` 在 `DirectRegion` 分支里已有的行为：

- 当前格已放马 → `OnWheelRecall()`；
- 该颜色已放在别的格子 → 小马摇头 + 提示「该颜色的小马已在棋盘上，请先请回」；
- 障碍格 → 提前拦下，不给召唤。

也就是说这个模式本来就已经写好了，此前只是没有被设为默认。

## 老存档兼容

`SummonMode` 的 0 是旧版本的「长按轮盘」，而它同时也是「从未动过设置」的默认值，无法从存档值本身
区分这两种情况。处理方式：

- `UXiaomaSaveGame` 新增 `bSummonModeMigrated`（默认 false），老存档反序列化后同样是 false；
- `MigrateSummonMode()`：第一次读到存档时，若 `SummonMode == 0` 就改成 2（直接放当前色），然后置标记；
- 之后玩家手动选回 0（长按轮盘）不会再被迁移，因为标记已经为 true。

新字段默认 false、老存档也是 false，正是迁移该触发的条件，所以**不需要升 `LevelRevision`**，
玩家进行中的对局不会被丢弃。调用点在 `AXiaomaGameMode::BeginPlay`，紧跟 `MigrateLevelRevision()`。

迁移结果要等到下一次 `SaveProgress()` 才落盘。中途退出会在下次启动重复迁移一次，行为完全一致（幂等）。

## 改动清单

- `Source/XiaomaLogic/XiaomaSaveGame.h`
  - 新增 `bSummonModeMigrated` 字段与 `MigrateSummonMode()`；
  - 更新 `SummonMode` 注释，标明 2 是默认值。
- `Source/XiaomaLogic/XiaomaGameMode.cpp`
  - `BeginPlay` 调用 `Progress->MigrateSummonMode()`。

`CycleSummonMode()` 的循环顺序（0 → 1 → 2 → 0）没有改：默认落在 2，点一下变 0（长按轮盘），
再点变 1（点击切换轮盘），再点回 2。

  `cl.exe @<obj>.rsp` + `link.exe @<dll>.rsp` 手工编译链接，产物同为 `Binaries/Win64/UnrealEditor-XiaomaLogic.dll`）。
- 自动化测试：`XiaomaLogic.Puzzle.AllLevels` 通过，`**** TEST COMPLETE. EXIT CODE: 0 ****`。
- 真机待验收：老存档进设置应显示「召唤方式：直接放当前色」；站到格子按召唤键直接放该色小马；
  同键再按一次请回；颜色已放别处时提示「请先请回」。

## 遗留

- 轮盘模式（0 / 1）里非法色的扇区仍然可点，点下去才被拒绝。若以后还想用轮盘，可以再把
  `OpenWheel` 里非当前色的扇区置灰（原方案 B），本次没有做。
- 已知缺陷：左键抚摸会命中每格常驻的隐藏小马组件，导致点空格子也涨好感，详见
  `左键抚摸误命中.md`。
