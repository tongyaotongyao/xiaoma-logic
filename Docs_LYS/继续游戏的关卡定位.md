# 继续游戏的关卡定位

> 对应问题：通关后不点「下一关」直接退出，再进游戏「继续游戏」跳到第 25 关（已解锁的最高关），而不是本应在的那一关。
> 记录日期：2026-11-27

## 1. 现象

- 通关第 N 关 → 不点「下一关」，直接关游戏；
- 重新打开 → 菜单点「继续游戏」→ 进入第 25 关（原话：「我推测应该是已解锁的最靠后的关卡」，推测正确）。

同样的问题还会出现在**生命耗尽**之后：失败也会清掉进行中的对局，退出再进同样跳到第 25 关，而不是回到刚失败的那一关。

## 2. 根因

`AXiaomaGameMode::GetContinueLevel()` 原来的实现：

```cpp
const int32 Unlocked = GetUnlockedLevel();
if (Progress && Progress->bHasActiveRound)
{
    return Clamp(Progress->ActiveLevel, 1, Unlocked);
}
return Unlocked;          // 没有续局就返回「已解锁的最高关」
```

通关时 `SubmitAnswer` 会做两件事：`bHasActiveRound = false`、`UnlockedLevel = Max(UnlockedLevel, N+1)`。于是退出再进走兜底分支，返回 `UnlockedLevel`。

**为什么以前看不出来**：正常进度下 `UnlockedLevel` 恰好等于 `N+1`，兜底返回值正好是「下一关」，看起来完全正确。开发用全解锁把 `UnlockedLevel` 写成 25 之后，兜底就永远返回 25。

**根子上的设计缺陷**：代码把「解锁到哪」当成了「玩家玩到哪」。这个等式只在「一次也没重玩过、也没手动解锁过」时成立。一旦重玩旧关（例如解锁到 20 关时回去打第 3 关），或者开发用解锁，两者就分叉了。

## 3. 修法

存档新增 `LastPlayedLevel`，把「玩家在哪」和「进度到哪」拆成两个字段。

| 字段 | 语义 |
|---|---|
| `UnlockedLevel` | 进度上限，决定关卡选择里哪些关可点 |
| `LastPlayedLevel` | **最后一次实际进入过的关卡**；通关时记成下一关（最后一关则停在最后一关）；`0` 表示老存档没有记录 |
| `ActiveLevel` | 有未完成的续局时，续局所在关 |

`UXiaomaSaveGame::GetContinueLevel(LevelCount)`：

```
有续局            -> ActiveLevel
否则有 LastPlayed -> LastPlayedLevel
否则              -> UnlockedLevel（老存档兜底，保持原行为）
```

返回值统一 `Clamp` 到 `[1, UnlockedLevel]`，再 `Clamp` 到关卡表长度，避免存档里的旧值越界。

写入点：

- `StartLevel()` 验证通过后：`LastPlayedLevel = LevelNumber`；
- `SubmitAnswer()` 通关时：`LastPlayedLevel = Min(Levels.Num(), N + 1)`；
- 失败（`Lost`）、重开（`RestartLevel`）不改它——它们本来就该停在当前关。

**不需要升 `LevelRevision`**：`LastPlayedLevel` 缺失时默认 `0`，正好落到「退回解锁进度」这条老路径，老存档不会突然「继续」到第 1 关，也不会因此丢掉续局。

## 4. 附带改动：菜单按钮写出关号

主菜单按钮由「继续游戏」改为「继续游戏（第 7 关）」。

原因：这次误判的一半来自按钮不告诉你它要进哪一关。写上关号之后，行为本身可核对——将来再出现跳错关，一眼就能看出是哪个环节错了，而不用先怀疑"是不是 bug"。

## 5. 验收

自动化（`XiaomaLogic.Puzzle.AllLevels`，已通过）覆盖 6 条：

1. 全新存档 → 第 1 关；
2. 老存档（`LastPlayedLevel = 0`，解锁 25）→ 25（退回解锁进度）；
3. 全解锁但玩过第 4 关 → 4（修复前会返回 25）；
4. 通关后记成 5 → 5；
5. 超过解锁进度（9 而只解锁到 6）→ 6；超过关卡表长度 → 夹到 25；
6. 有续局时以续局为准。

真机需要确认：

- 进第 6 关玩几步 → 退出 → 再进，「继续游戏（第 6 关）」→ 回到第 6 关原位置；
- 通关第 6 关 → 退出 → 再进，按钮显示「第 7 关」，进去是第 7 关起点；
- 生命耗尽 → 退出 → 再进，按钮显示刚失败的那一关。

## 6. 一个必须提醒的点

**现有存档的 `LastPlayedLevel` 是 0**，所以修完之后第一次进游戏，「继续游戏」仍会显示第 25 关——这是老存档兜底，不是没修好。只要进入任意一关（走关卡选择也行）再退出，这个字段就有值了。想立刻生效可以：

```bash
python Tools/unlock_save.py --unlock 6    # 把解锁数压到目标关，兜底自然落对
```

## 7. 顺带发现的构建环境坑

本次 `Build.bat` 直接崩在 UBT 里：

```
Unhandled exception. System.ArgumentException:
Path fragment '"Docs_LYS/\345\255\230\346\241\243\345\215\207\347\211\2105.md"' contains invalid directory separators.
   at UnrealBuildTool.GitSourceFileWorkingSet.AddPath(...)
```

UBT 为了做自适应 unity 编译会跑 `git status` 取工作集，而 git 默认把非 ASCII 路径转义成带反斜杠的八进制（`core.quotepath=true`），UBT 把它当路径解析就炸了。**只要 `Docs_LYS/` 里有未跟踪的中文文件名，构建就会崩**，与代码无关。

- `-DisableAdaptiveUnity` 试过，无效（该参数没被吃到）；
- 可用做法：给这次构建的 git 子进程关掉转义，不改任何 git 配置与仓库状态：

```bash
GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.quotepath GIT_CONFIG_VALUE_0=false \
  "D:/EpicGames/UE_5.5/Engine/Build/BatchFiles/Build.bat" \
  XiaomaLogicEditor Win64 Development -Project="D:/Desktop/xiaoma-logic/XiaomaLogic.uproject" -WaitMutex
```

- 彻底解决需要版本控制侧配合（把 `Docs_LYS/` 提交跟踪，或加进 `.gitignore`）——按约定这件事由用户决定。
