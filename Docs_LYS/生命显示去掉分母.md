# 生命显示去掉分母（`2/5` → `2`）

> 状态：已改完，编译与 `XiaomaLogic.Puzzle.AllLevels` 通过。2026-11-27。

## 现象

第 11 关以后满血进关，HUD 显示「生命 2/5」，看起来像**掉过 3 条血且没回满**。
真机验证过死亡重试，第 14 关死后拿回来的确实是 2 条，数值链路没有问题。

## 原因

- `levels.json`：第 1~10 关 `lives = 3`，第 11~25 关 `lives = 2`。
- HUD 的分母来自 `AXiaomaGameMode::GetMaxLives()`，**写死返回 5**。
- 5 其实只是吃苹果的上限（`XiaomaGameMode.cpp` 里 `FMath::Min(5, CurrentLives + 1)`），并不是本关初始生命。
- 于是「2 条满血」和「5 条上限」被拼成 `2/5`，语义对不上。

## 改法（采用方案 A：不带分母）

`XiaomaHUDWidget.cpp`：

```cpp
// 生命不带分母：各关初始生命不同（1~10 关 3、11 关起 2），吃苹果最高到 5，
// 原先恒写 "/5" 会让满血看起来像掉过血。
AddText(Panel, FString::Printf(TEXT("生命 %d  ·  步数 %d/%d"),
    Game->GetLives(), Game->GetStepCount(), Game->GetParSteps()), 16, Gold);
```

`XiaomaGameMode.h`：删掉 `GetMaxLives()`。改完之后它已无任何引用（全仓只有 HUD 那一处调用），
留着这个写死 5 的接口容易在将来被再次误用。

这是全仓唯一一处展示生命的地方，失败界面、菜单都没有引用。

## 为什么不用其他方案

- **分母改成本关初始（`2/2`）**：吃苹果后会变成 `3/2`，得再补判断把分母跟进成 `3/3`，掉血后又缩回，读起来更绕。
- **保留 `/5` 加注「上限 5」**：信息最全也最啰嗦，而「上限 5」对当前这关没有实际意义。

玩家的真实关切是「还能挨几下」，所以只显示当前值最干净。以后如果真做了回血类道具、
血量变成需要规划的长期资源，再考虑补一行上限说明。

## 验收

1. 第 1~10 关进关：`生命 3`。
2. 第 11 关以后进关：`生命 2`（不再出现 `/5`）。
3. 被捣蛋鬼撞一次：数字减 1。
4. 吃苹果：数字加 1，最高到 5。
5. 死亡重试：回到本关初始值。
