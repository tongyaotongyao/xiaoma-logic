## 1. 规则

某个色区四周立起矮栏杆，**主角进不去区域内的格子**。区域外摆一块同色踏板，踩上去围栏**永久打开**：

- 开关踩一次就开，**不能手动关上**；
- 打开后栏杆消失、踏板压暗，那块地从此随便进出；
- 想「把门关回去」只有一条路：按 `Z` 撤销到踩开关之前。

围栏**只挡主角**。小马照样能入驻区域内的格子，木箱、捣蛋鬼也不受影响（校验层直接不允许围栏与这两者同关，见第 5 节）。

它是全部阻碍里唯一允许盖住正解格的一种。石头、冰面、木桥都只能逼玩家绕路；围栏能做的事是把「什么时候进这个色区」变成谜题的一部分：正解格被封在里面，玩家必须先跑到开关、再回来。

## 2. 为什么是一次性开关

策划案写的是「踩下开关后打开，再踩一次关上」。做成可反复开关会立刻撞上死锁：

- 开关在**区域外**：玩家开门进去以后再也踩不到开关，「再踩一次关上」永远用不上；
- 开关在**区域内**：门关着时区域根本进不去，外面的人踩不到开关，开局就锁死。

要同时支持反复开关，只能把开关做成「围栏上的门格」——门格永远通行、其余区域格被挡，玩家站在门格上关门，随时能再踩开。规则能自洽，但要多一条「门格例外」、多一套「人被关在里面怎么办」的判定，而收益只是「玩家可以主动关门」，没有任何玩法支撑（捣蛋鬼的隔离已经有 `F` 标记这个更明确的工具）。

一次性把这些问题一次消掉：

| 问题 | 一次性方案下的状态 |
|---|---|
| 开关放哪 | 门关着 → 区域内不可进 → 开关**只能在区域外**，玩家永远不会站在被封锁的区域内 |
| 玩家被困 | 不存在。区域内进得去的时候，门已经开了，且不会再关 |
| 「关回去」 | 交给 `Z`。撤销本身就是「从历史里取一个状态」，比手动开关更干净 |
| 状态 | 1 字节 |
| 存档兼容 | 旧续局没有围栏，新增机关只往后追加，下标不会错位 |

## 3. 数据结构

```json
"adventure": {
  "gates": [
    { "region": 2, "switch": [3, 3] }
  ]
}
```

- `region`：被围住的色区编号 `0~5`，运行时由盘面 `regions` 反查区域格，JSON 里**不重复写格子**（写两处迟早对不上）。
- `switch`：开关格，校验工具强制它在区域外、且站得住。
- 围栏是**机关**（`AXiaomaGate`，继承 `AXiaomaMechanism`），有开/关状态，要进撤销快照和存档，1 字节（`0` 关 / `1` 开）。
- 围栏进 `AdventureFingerprint`（区域 + 开关格都算）：机关状态是按 `Mechanisms` 下标写存档的，围栏的顺序一变，旧续局的「开/关」就会配到别的围栏上。

## 4. 实现要点

**状态机（`XiaomaGate.h/.cpp`）**

| 事件 | 行为 |
|---|---|
| `BlocksCell(Cell)` | 门关着且 `Cell` 在本区域内 → true；开关格在区域外，不受影响 |
| 主角踩上开关格 | 先广播 `OnOpened`（此刻 `bOpen` 还是 false）→ GameMode 压快照 → 再 `Open()` |
| `SaveState/LoadState` | 1 字节；`LoadState` 后按状态重刷视觉 |
| `ForceOpen()` | 不广播、不压快照，只给「存档不一致」兜底用 |

**撤销落点**：`OnGateOpened` 压完快照后，直接把栈顶那一条改写成「踩开关之前」——`HerdsmanCell` 换成 `Herdsman::GetPreviousCell()`、`StepCount` 减 1（踩开关那一步在 `OnHerdsmanCellChanged` 里已经计入）。所以按一次 `Z` 的净效果是：**人退回上一格、步数退一步、围栏重新关上**，和「这次开门没发生」完全一致。

这套做法和塌陷木桥的 `ApproachCell` 是同一个套路：状态变更**前**压快照，再把快照改写成变更前的样子。区别在于桥要减 2（进桥、离桥各一步），围栏只减 1。

**恢复路径绝不压快照**：`EnsureGateConsistency()` 只在「人已经在栏内、门却关着」时调 `ForceOpen()`，不广播、不压快照。这个组合正常玩不出来，只在存档/快照拼接出错时出现，兜底开门总比把人卡死在原地好。它挂在三处：`StartLevel` 读档后、`Undo()` 之后、以及每次生成机关之后。

**生成顺序**：围栏排在 **木桥之后**（障碍 → 宝箱 → 木箱 → 道具 → 捣蛋鬼 → 木桥 → 围栏）。新类型只往后追加，21 关以前的存档没有围栏，已有续局的机关下标不会被顶歪。

**视觉**：区域边界上「邻居不在本区域」的每一条边立一段横栏（长 112、截面 9×9、中心 z=22）+ 一根立柱（高 30、贴着地板插进去）。区域内部的边不立，所以围栏是沿着色区的形状绕一圈，不是画个正方形。开门时栏杆整体隐藏、按钮下沉 4.5 个单位并压暗到 55% 亮度，留一块「用过的踏板」在场上。颜色一律取 `XiaomaPalette::Regions[region]`，木头再压暗到 72%，免得和同色地砖糊成一片。

## 5. 校验工具

`Tools/validate_adventure.py`：

- `gates` 从「尚未实现的机关」名单移除，正式解析，棋盘预览新增 `|`（区域格）与 `G`（开关格）两个符号。
- **可达性与 `min_steps` 再叠一维**：状态从 `(格, 已踩目标, 已塌桥掩码)` 扩成 `(格, 已踩目标, 已塌桥掩码, 已开围栏掩码)`。踩到开关格（含滑行经过）就把对应位打上，之后整个色区解锁。围栏数量少，掩码规模可以忽略。
- 新增守卫（都是错误）：

| 检查 | 理由 |
|---|---|
| 开关在自家区域内 | 门关着时区域进不去，永远踩不到，开局锁死 |
| 开关与障碍 / 木桥 / 冰面 / 宝箱 / 木箱 / 道具同格 | 站不住，或者站上去也触发不了 |
| 起点在围栏区域内 | 一进关就被关在里面 |
| 同一色区两道围栏 | 区域格重叠，开门状态互相打架 |
| 两个围栏开关同格 | 踩一下同时开两道门，规则上说不通 |
| 巡逻路线进入围栏区域 | 门是动态的、路线是静态的，会出现「开门前撞墙、开门后突然进来」，玩家没法预判 |
| 围栏与冰面 / 木箱 / 木桥同关 | 区域级开关叠上逐格状态（滑行、推箱、塌桥），规则和搜索都会变得解释不清，先不同关 |

- 新增提示（不是错误）：开关正好是主角起点时，一进关门就开了，这道围栏等于没有。

## 6. 关卡

| 关 | 围栏 | 开关 | 最短/par | 设计意图 |
|---|---|---|---|---|
| 21 | 色区 2（(1,4)(1,5)(2,4)(2,5)） | (3,3) | 19→**21** / 25→**28** | **首现**。正解格 (2,4) 在右上那个四格色区里，围栏一立，玩家必须先从起点走到盘面中部的踏板，再折回右上。区域里没有任何道具或宝箱，第一关只学「围栏 + 踏板」这一件事 |

**关于 par 只涨 2 步**：21 关的 6 个正解格散布全盘，最短路径本来就绕着整张图走，任何开关位置最多只能多绕 2 步（把 30 个候选格逐一试过，最大值就是 21）。这不是配错了，而是这张盘的形状决定的。所以围栏在 21 关的分量主要来自「必须先理解它存在」，而不是步数惩罚。

想让围栏真正有压力，只能靠另外两条路，留给 22~25 关：

1. **围住宝箱或道具**——区域里放着必须拿的东西，一次开门要同时兑掉「放马」和「开箱」；
2. **两道围栏互相牵制**——A 的开关在 B 的区域内，逼出「先开哪道」的顺序（搜索会自然检出死锁）。

## 7. 与策划案的取舍

**可反复开关 → 一次性开启。** 理由见第 2 节。策划案 §4 的「再踩一次关上」没有给出任何玩法支撑，而它带来的死锁判定成本明显更高（捣蛋鬼的隔离已经有 `F` 标记）。

**围栏与冰面 / 木箱 / 木桥不同关**（策划案没提）。滑行冲过关闭的围栏、推箱状态里再叠开门状态、桥塌与开门两套不可逆状态叠一起，三件事都需要额外定义规则。21~25 关的设计重点是「围栏 + 组合宝箱」，先把这条链路做干净。

**围栏首现放在第 21 关**，与策划案 §7 节奏表一致。
