# 巡逻捣蛋鬼（M4 第一项）

> 规则依据 `ADVENTURE_DESIGN.md` §4 与 §7 节奏表（只读参考，未修改）。视觉暂用基础几何体。

## 规则

- 沿 `levels.json` 给出的路线在格子中心之间**匀速往返**，速度恒定；
- 撞到主角：扣 1 命，主角被弹回本关起点；
- `F` 放下的 `X` 标记对它是**路障**，碰到掉头——这是第 11~15 关的核心技巧；
- `Z` 撤销或读档时，它回到路线起点重新走；
- 路线**可以穿过**正解格，但两个停留端点不能压在正解格上（校验器检查）。

## 数据格式

```json
"adventure": {
  "patrols": [
    { "path": [[5, 2], [5, 3], [5, 4], [5, 5]], "speed": 1.0 }
  ]
}
```

- `path` 必须**逐格写全**，相邻两点只能上下左右差一格。只写首尾两点会被校验器报「不相邻」。
- `speed` 单位是**格/秒**，合法区间 0.2~8，缺省 1.5。一格 112 cm，所以 `speed = 1.5` 约等于 1.7 m/s，比主角（340 cm/s 基准）慢，玩家有反应时间。
- 路径少于 2 个点时整条被丢弃并打日志，不会连累同关其他数据。

## 实现

新增 `Source/XiaomaLogic/XiaomaPatroller.{h,cpp}`，继承 `AXiaomaMechanism`：

| 关注点 | 做法 |
|---|---|
| 移动 | 不用「当前格 + 目标格」推进，而是用一个连续的行程标量 `TravelDistance`（单位：格）。每帧 `+= 方向 × speed × dt`，越过端点就把多走的距离折回来并反向，卡顿时会连折几次也不会飞出去 |
| 位置 | `Lerp(格子中心, 下一格中心, 小数部分)`，因此格与格之间是平滑滑行，不是跳格 |
| 朝向 | 格子坐标是 `(行, 列)`，世界坐标 X 随列减小、Y 随行减小，所以方向要取反再算 `Atan2`；不取反的话它会倒着走 |
| 撞人 | 每帧比自己所在格与主角所在格（按「走过半格才算进下一格」取最近格）；命中后设 1 秒冷却，避免主角刚被弹回起点又被同一只连扣 |
| `X` 挡路 | `OnBoardChanged` 缓存整张棋盘；**每帧先判前方通不通，再决定走还是掉头**（详见下一节）。掉头时沿新方向挪 0.02 格，否则会在整数边界上反复判定同一格而抖动 |
| 被夹死 | 前方与后方都不可走时置 `bStalled`，原地停住不动不转；`X` 标记一变就解除 |
| 撤销/读档 | `SaveState` 留空、`LoadState` 一律 `ResetToStart()`。存档里每个机关占 0 字节，正好符合「撤销后回起点重走」 |
| 暂停 | `SetScreen` 里按 `Playing` 与否逐个 `SetPatrolEnabled`，否则会在暂停界面里继续走动甚至撞人 |

## 被 X 堵住时停住（2026-11-27 修，两轮）

### 第一轮：先判定再推进（不够）

真机验收时发现：把 `X` 放在捣蛋鬼前后两侧，它会**原地每帧翻转一次朝向、位置在两厘米之间来回抖**。

第一轮改成「先判定前方、再推进，两侧都不通就 `bStalled`」。夹死场景确实停了，但用户随后发现**朝向会影响是否抽搐**——同一个位置，有的方向停得住，有的抖。

### 第二轮（当前）：直接用可行区间

枚举模拟（路径 2~5 点 × 全部 X 组合 × 速度 × 起始位置 × 方向）复现出 92 个抽搐组合，全部是同一形态：**起点格被标 `X`、它在紧邻的端点附近**。原因在地处判定方法的粒度：

- 向后退时，「紧接着要踏入的格」用 `floor(t - eps)`，当 `t` 已经在 0.97（属于第二格）时它算出第一格，于是认为「再退就进 X 格」而掉头；
- 掉头后 `nudge` 把 `t` 推出端点，被 `Clamp` 钉回端点，下一帧必然又越过端点折返；
- 折返回来又立刻被判「要进 X 格」→ 掉头 → 循环，周期正好一帧。

也就是说：**只要它被挤在一格宽的边角里，逐帧试探就一定会打转**，跟朝向有关只是因为不同起始方向进入循环的相位不同。

现在的做法（`RecomputeBounds()`）：

1. `X` 标记的格整格不可进入，等价于「格心 ± 半格」这段行程是墙；
2. `OnBoardChanged` 时从当前位置向左右各找最近一道墙，得到可走区间 `[MinTravel, MaxTravel]`；
3. `Advance()` 只在区间内推进，撞到边界就把越过量折回来并反向——**不再有逐帧试探，也就不存在极限环**；
4. 区间宽度 `< 0.75 格`（`MinTravelSpan`）时判定 `bStalled`：剩下的空间不够它正常走一趟，往返只会变成原地打转，停住反而更像「被堵住了」；
5. `X` 正好落在脚下时（撞人冷却期间玩家放的），把位置推回最近的可站边界。

因为边界是精确算好的浮点值，掉头时把超出量减回去，位置不会钉在界上反复触发。

### 两轮都保留的部分

- 停住期间仍然每帧执行撞人判定——站着的捣蛋鬼也是一只捣蛋鬼，主角走进它所在格照样该被撞。
- 恢复条件：`OnBoardChanged` 里比较新旧 `Cells`，**只有 `X` 标记真的变了**才重算。召唤小马、用提示星也会走到这个回调，若无条件重算，停住的捣蛋鬼会被反复唤醒又停回去。

### 验证

同一套枚举（路径 2~5 点 × 1~5 个 X 的任意组合 × 速度 1.0/1.6/3.0 × 11 个起始位置 × 两个方向）：**抽搐组合 0 个**。

| 场景 | 可走区间 | 宽度 | 结果 |
|---|---|---|---|
| 2 点、起点被标 | [0.50, 1.00] | 0.50 | 停住，位移 0 |
| 2 点、终点被标 | [0.00, 0.50] | 0.50 | 停住，位移 0 |
| 3 点、中间被标 | [0.00, 0.50] | 0.50 | 停住，位移 0 |
| 4 点、两端被标 | [0.50, 2.50] | 2.00 | 正常往返，600 帧翻转 8 次 |
| 4 点、中间夹住 | [1.50, 1.50] | 0.00 | 停住，位移 0 |
| 4 点、无标记 | [0.00, 3.00] | 3.00 | 正常往返，600 帧翻转 5 次 |

性能上原本也不是问题（每帧几次浮点，单帧远低于 1 微秒）；现在停住时连 `SetActorLocation` / `SetActorRotation` 都省了。

## 与既有系统的接线

- `AXiaomaGameMode::SpawnAdventureActors` 生成，挂进 `Mechanisms`，因此 `IsCellBlocked`、撤销快照、存档编解码全部自动覆盖（它不阻挡格子，`BlocksCell` 保持基类的 `false`）。
- 撞人回调 `OnPatrollerHitHerdsman`：**先** `TeleportToCell(起点)` 再 `LoseLife()`。顺序不能反——`LoseLife` 内部会立即落盘，反了就会把「被撞时那一格」写进存档续局。
- 撞人**不额外压撤销快照**：`PushUndoSnapshot` 记录的本来就是上一次玩家操作前的状态（含生命），按 `Z` 自然会退回去，没必要在受伤瞬间再插一帧。
- `ToggleMarkAtCurrentCell` 与 `Undo` 补了 `NotifyMechanismsBoardChanged()`——标记变化以前只刷 UI，机关收不到，捣蛋鬼会拿着旧棋盘数据撞穿路障。
- `AdventureFingerprint` 纳入巡逻（路径 + 速度）。机关状态按索引存进续局，路线一改就必须让旧续局失效；因为指纹变了会自动丢弃，**这次不用升 `LevelRevision`**。
