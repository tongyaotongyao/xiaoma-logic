# 冰面滑行（M4）

> 状态：已完成并编译通过，`XiaomaLogic.Puzzle.AllLevels` 通过，52 个 Python 用例全过。2026-11-28。
> 策划案出处：`ADVENTURE_DESIGN.md` §4「阻碍与机关」（第 16 关首现）、§6.1 `ice` 字段、§11 M4。
> 与策划案的一处**有意偏差**见第 7 节。

## 1. 规则

踩上冰面就再也站不住：沿**进入方向**一直滑，滑行中**完全忽略输入**，直到

- **滑出冰面** —— 落在冰后面第一块普通地板上（会冲过头，这就是冰面的难点）；
- **撞上墙、障碍或机关** —— 停在最后一块冰上，那一格就成了"冰上落脚点"。

三条落地细节：

| 细节 | 选择 | 理由 |
|---|---|---|
| 滑行结束要不要吸附格心 | **不吸附** | 玩家已经有一格高亮显示自己在哪；滑行是连续位移，硬拽到格心会看出"瞬移" |
| 滑行速度 | 常速 ×1.2 | 比走路快一点才像打滑，又不至于看不清停在哪 |
| 冰面能不能放东西 | **道具、宝箱、木箱、符文、石碑都不能** | 滑过去停不住，玩家拿不到也开不了；校验工具会直接报错 |

滑行期间**不推箱**：撞到木箱就停下，免得一口气推好几格。冰面关和推箱关因此不混用（校验工具报错拦截）。

## 2. 数据结构

```json
"adventure": {
  "ice": [[1, 4], [2, 4], [3, 4], [4, 4]]
}
```

- 只记格子坐标，顺序无所谓，重复会被解析层去重、也会被校验工具报错。
- 冰面**不是机关**：不占格、不挡路、没有状态，所以不进 `Mechanisms`，撤销/存档都不需要为它存字节。
- 但它是**地形**：改一次冰面，续局里主角站的那一格可能已经站不住了，所以 `AdventureFingerprint` 把 `ice` 算进去，旧续局自动失效（不必升 `LevelRevision`）。

## 3. 实现要点

**判定（`AXiaomaHerdsman`）**

- `SetIcePredicate` 由 GameMode 注入，读当前关的 `ice` 列表；`IsIceAt` 每帧查一次，`TArray::Contains` 在这个规模下没有性能问题。
- **判定看"脚下这一格"**，而且用 `WorldToRawCell`（50% 越界即换格），不是带 12% 缓冲的 `CurrentCell`：一踩上去就得开始滑，不能等走进 62% 才反应。
- 斜着踩上冰面时只能滑一个轴：`BeginSlide` 取输入分量更大的轴；正好 45° 时取"已经越过格心更多"的那一轴，避免贴着格子边走反而横着滑出去。
- `bSliding` 为真时，`Tick` 里的 `Dir` 直接被 `SlideDir` 顶替，玩家输入完全不生效（包括松手——松手不会停）。
- 撞死了（这一帧没位移）就 `EndSlide()`，玩家立刻拿回控制权；滑出冰面时同样 `EndSlide()`，并**强制同步一次所在格**（`SyncCurrentCellNow`）。后者是为了修一个手感问题：滑出冰面时角色可能停在新格子的边上，而带缓冲的格子更新还没触发，高亮会留在上一格。
- 死亡、暂停、结算（`SetMovementEnabled(false)`）、传送（`TeleportToCell`：撤销/读档/挨撞弹回）都会清掉滑行状态，不会带着惯性乱滑。
- 滑行时脚下跳动幅度从 7 降到 2：冰上是滑不是跑，跳着滑看着别扭。

**视觉（`XiaomaIceField.h/.cpp`，新文件）**

- 每格一片浅蓝圆盘（直径 94、厚 5，顶面 z≈13，比地板顶面 8 高 5，不会把主角和小马的脚埋进去），中心再叠一层更亮的薄片做透光感。
- 相邻冰格之间补一条细冰条，把圆盘连成一条完整的冰道（列号 +1 → 世界 X −112，行号 +1 → 世界 Y −112）。
- 全部部件 `NoCollision` + 不投影：不挡主角、不挡鼠标射线（点地板召唤小马照常生效）。
- 冰面没有状态，所以**不进 `Mechanisms`**；GameMode 用单独的 `IceField` 指针持有，换关时在 `ClearAdventureActors` 里销毁重建。

## 4. 关卡

| 关 | 冰面 | 设计意图 |
|---|---|---|
| 16 | `(1,4) (2,4) (3,4) (4,4)`：纵向 4 格冰道 | **首现**。从下面滑上去会冲过一格，正好落在三叶草 (0,4) 上，然后必须绕 (0,5) 才回得到 (1,5)。教"冰上没有刹车"。最短 20 步，par 26，绕开冰面要 21 步 |
| 17 | `(3,2)…(3,5)` + `(2,4) (2,5)`：L 形 | 一段横向滑到桌边停在正解格 (3,5)（**只能这么上去**），另一段从 (4,4) 往上滑，正好落在正解格 (1,4)。最短 21 步，par 25 → **28** |

第 17 关的冰面是**必要**的：把冰格当成墙，正解格 (3,5) 就永远到不了。这一点写进了 Python 用例 `test_level_seventeen_needs_the_ice`，以后改冰面忘了这层语义会直接红。

## 5. 校验工具

`Tools/validate_adventure.py`：

- `ice` 从"未实现机关"名单里移除，正式解析。
- 新增 `slide_step(cell, direction, walkable, ice)`：返回 `(落点, 跨过的格数)`，把上面两条停止规则都写进一个函数；`reachable` 与 `min_steps` 都改走它。
- **步数与游戏内计数一致**：滑行跨 4 格就记 4 步，不是 1 步。所以 `min_steps` 从广度优先换成 Dijkstra（边权 = 跨过的格数）——否则冰面会变成白赚步数的捷径，par 也跟着虚高。没有冰的关卡每条边权都是 1，结果与原来的广度优先完全一致。
- 新增检查：冰面与障碍/道具/宝箱/木箱/压力板同格 → 错误；冰面关配木箱 → 错误；冰面关配符文或石碑宝箱 → 错误；起点在冰面、孤立单格冰 → 提示。
- 棋盘预览新增符号 `~`，`--level N` 会多打一行冰面坐标。

## 7. 与策划案的偏差（有意）

`ADVENTURE_DESIGN.md` §8 的检查项 2 写「障碍、**冰面终点**、木桥、巡逻停留点都不在正解格上」，第 17 关的 (3,5)、(1,4) 恰好都是"冰面终点"式的落点，是**故意**这么设计的。

原因：策划案这条规则的顾虑应该是"落点不精确、玩家不知道该站哪"，但本作的落点是确定的——

- 撞墙停在最后一块冰上：落点紧贴棋盘边界，离格心 36 单位（格宽 112）；
- 被障碍挡住时停在半格线上，离格心最多 56 单位，仍在同一格内；
- 滑出冰面落在紧邻的普通地板，落点由几何关系唯一确定；
- 再加上现有的"所在格高亮"，玩家不会站错格。

如果连冰面终点都禁止落在正解格上，冰面就只能当纯减速带，做不出"必须滑到墙边才够得到"这类谜题。所以这条规则在本作**不执行**，改为：正解格可以落在冰面终点，但必须通过可达性搜索（`reachable` 已经带滑行语义）证明真的能停下来。真正让人卡死的摆法（比如正解格在冰道中间、永远停不住）依然会被判错：起点到不了正解格 → 直接报错。
