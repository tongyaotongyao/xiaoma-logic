# 推箱子宝箱（M4）

> 状态：已完成并编译通过，`XiaomaLogic.Puzzle.AllLevels` 与 39 个 Python 用例全过。2026-11-27。
> 真机第一轮发现并修复了两个问题：**推动方向左右上下错位 90°**、**压力板埋在地板底下看不见**，见文末两节。
> 策划案出处：`ADVENTURE_DESIGN.md` §5「推箱子」、§6.1 `boxes` 字段、§11 M4。

## 规则（按策划案）

> 把木箱推到压力板上，宝箱打开。推箱沿用障碍判定，不能推出棋盘。

落地时定下的四条细节：

| 细节 | 选择 | 理由 |
|---|---|---|
| 推动方式 | **按格推**，箱子整体前进一格（0.12 秒补间） | 主角是自由移动的，连续推要处理半格卡墙、绕行、快速换向一堆边界；按格推的判定全在格子坐标上，存档/撤销只需要一个格索引 |
| 对捣蛋鬼 | **不阻挡** | 捣蛋鬼是漂浮的；让它被箱子挡住会引入"被箱子卡住"这类新的抽搐问题 |
| 压力板 | **一次性锁存** | 箱子推到就永久开箱，推走也不重锁；否则会出现"宝箱开着但板子空着"的展示矛盾 |
| 推动方向 | 沿主角输入的分轴方向推，斜着走时两轴各自独立判定 | 与既有"分轴推进、贴墙滑行"的移动手感一致 |

## 数据结构

```json
"chests": [
  { "cell": [0, 0], "reward": "hint", "puzzle": { "type": "push", "plate": [0, 3] } }
],
"boxes": [ { "cell": [2, 3] } ]
```

- **压力板只记在宝箱上**（`puzzle.plate`），木箱只记自己的初始格。
  同一个坐标写两处迟早会对不上，所以没有采纳最初设想的"每只箱子自带 plate"。
  "哪只箱子推哪块板"由校验工具把关：只要存在一条推行路径即可，不指定具体哪一只。
- `FXiaomaChestDef::PushPlate`（默认 `(-1,-1)`）、`FXiaomaBoxDef::Cell`、`FXiaomaAdventureData::Boxes`。
- `puzzle.box` 字段**已废弃**，写了会被校验工具报错。

## 实现要点

**`AXiaomaPushBox`（写在 `XiaomaMechanism.h/.cpp` 里，没有新文件）**

- `BlocksCell(Cell)` 返回 `Cell == BoxCell`，所以自动接进现有的 `IsCellBlocked`：
  主角走不进箱子格、也不能在箱子格上召唤小马。
- 状态一个字节：`X * 6 + Y`；`LoadState` 用「初始格 → 当前格的差」自己算世界坐标
  （列号加一 X 减一格、行号加一 Y 减一格），因此箱子不需要持有棋盘指针。
- 位移用 `VInterpTo` 补间，避免一格一格瞬移。

**推动链路**：主角 → GameMode → 箱子

1. `AXiaomaHerdsman::Tick` 里把原来的 `!IsBlockedAt(TryX)` 换成 `CanEnterOrPush(TryX, StepDelta)`。
2. 被挡住时调 `CellPush` 委托（`FXiaomaHerdsmanPushDelegate`），GameMode 判断挡路的到底是不是箱子。
3. `AXiaomaGameMode::TryPushBoxAtCell`：
   - `CanBoxEnter` 判定目标格：越界、障碍、别的箱子、宝箱格、石碑格、**还没捡的道具格**都不能进；
   - 通过后 `PushUndoSnapshot()` → `MoveToCell` → `RefreshPushPlates(true)` → 标脏。
4. `RefreshPushPlates` 检查每只推箱宝箱的压力板上有没有箱子：有就 `SetPlatePressed(true)` + `UnlockByMechanism()`。

**为什么箱子不会被一帧推飞**：目标是"进入箱子的那一格"才触发推动，推完箱子已经在下一格，
主角要走完自己这一格才会再次触发，所以推动频率天然被移动速度限住。

**为什么可以在 Tick 里压撤销快照**：拍照时主角还在箱子后面、箱子还没动，
按 `Z` 会同时把主角和箱子恢复到推之前，不会出现"人退回去了箱子留在前面"。

**存档与续局**：箱子挂进 `Mechanisms`，撤销快照与存档编解码自动覆盖。
`AdventureFingerprint` 已把 `Boxes` 与 `PushPlate` 纳入，关卡数据一改旧续局自动失效，不用升 `LevelRevision`。

## 顺手修掉的一个旧 bug

`AXiaomaChest::OnBoardChanged` 原来不分谜题类型，一律跑「行/列/色区」规则。
符文宝箱与石碑宝箱的 `RuleType` 默认是 `Row + 0`，于是**第 6~10 关的符文/石碑宝箱
只要在第 0 行摆对小马就会自己弹开**，绕过了谜题。

现在开头直接 `if (Def.PuzzleType != Rule) return;`，三种非规则谜题各走各的触发路径。

## 真机验收

1. 进第 13 关就能看见 (0,3) 那格有一块深灰圆盘 + 四颗铆钉 + 中间暗铜色指示片。
2. 四个方向各推一次：箱子朝着主角走的方向走一格（不再左右上下错位）。
3. 第 13 关撞上 (2,3) 的木箱，箱子向上挪一格，主角跟进；连续顶会一格一格推。
4. 把箱子推到 (0,3) 压力板：铁盘变暖色、指示片变亮、宝箱立刻弹开，状态栏提示去领取。
5. 把箱子从压力板上推开：宝箱**仍然开着**（锁存），板子恢复冷灰。
6. 推箱子撞棋盘边、撞障碍、撞另一个箱子、撞宝箱格：推不动，主角也走不进去。
7. 按 `Z`：箱子和主角一起回到推之前。
8. 推完退出重进：箱子在存档里的位置，不是初始位。

## 真机问题一：推动方向差 90°（已修）

现象：往上推箱子往右走、往下推往左走、往左推往下走、往右推往上走。

根因不在箱子，而在**主角这一侧把世界轴当成了格子轴**。
`CanEnterOrPush(Target, StepDelta)` 的 `StepDelta` 约定是**格子增量 `(行, 列)`**，
`TryPushBoxAtCell` 直接拿它做 `BoxCell + StepDelta`。但调用处传的是世界坐标轴的符号：

```cpp
// 修前
CanEnterOrPush(TryX, FIntPoint(RoundToInt(Sign(Dir.X)), 0));  // 世界 X → 当成了行增量
CanEnterOrPush(TryY, FIntPoint(0, RoundToInt(Sign(Dir.Y))));  // 世界 Y → 当成了列增量
```

棋盘映射是 `世界X = (5 - 列) × 112`、`世界Y = (5 - 行) × 112`（与小马用的 `CellToWorld` 完全一致），
所以沿世界 **+X** 走等于**列号 −1**、沿世界 **+Y** 走等于**行号 −1**。
轴和正负同时错位，正好得到一张 90° 旋转表：

| 操作 | 世界轴输入 | 修前传的格子增量 | 箱子实际去往 |
|---|---|---|---|
| W 上推 | +Y | `(0, +1)` 列 +1 | 屏幕右 |
| S 下推 | −Y | `(0, −1)` 列 −1 | 屏幕左 |
| A 左推 | +X（屏幕左） | `(+1, 0)` 行 +1 | 屏幕下 |
| D 右推 | −X（屏幕右） | `(−1, 0)` 行 −1 | 屏幕上 |

修法：在 `XiaomaHerdsman.cpp` 的匿名命名空间里加一个换算函数，把这条规则收到一处：

```cpp
FIntPoint WorldAxisToCellDelta(int32 WorldX, int32 WorldY)
{
    return FIntPoint(-WorldY, -WorldX);
}
```

调用处改成 `WorldAxisToCellDelta(StepX, 0)` / `WorldAxisToCellDelta(0, StepY)`。
`BoxCell`、`SaveState`、`LoadState`、`CanBoxEnter`、压力板判定用的本来就是格子坐标，一行没动。

> 注意 `PlayerController` 里「面向 +Y 时屏幕右侧为 −X」那两行反号是对的，问题只在推箱这一处。

## 真机问题二：压力板埋在地板里（已修）

现象：第 13 关完全看不到压力板在哪一格。

根因是高度。地板 `Tile` 缩放到 15 高、中心在 z = 0，**顶面在 z ≈ 8**
（旁证：宝箱底座正好从 z = 8 起，小马摆在 z = 10）。而压力板原先画在
`z = 2`、厚度只有 4 个单位，跨 0~4，整块在地板内部，看不见。

改成踩在地板面上，并补了几个部件让它一眼能认出来：

| 部件 | 形状 | 尺寸 | 高度 | 作用 |
|---|---|---|---|---|
| `PlatePad` 底盘 | 圆柱 | 直径 86 | z 2~16 | 主体，压住时由冷灰转暖色 |
| `PlateBolt` ×4 | 立方 | 6 × 6 × 6 | z 13~19 | 四角铆钉，机械感，和地板色块区分 |
| `PlateGlow` 指示片 | 圆柱 | 直径 52 | z 14.6~18.6 | 常亮，暗铜色 / 压住后亮黄 |

`SetPlatePressed` 相应改成**只改颜色、不再切换可见性**——
原先指示片只在压住时才显示，等于没压住时玩家看不到任何"目标点"提示。

半径 86 略小于一格 112，板子完整落在一格之内，不会压到相邻格。
