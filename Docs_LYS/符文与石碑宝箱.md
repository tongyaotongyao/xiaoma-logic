# 符文宝箱与石碑宝箱（M3）

> 日期：2026-11-27
> 范围：`AXiaomaChest` 的两种新谜题、第 6~10 关数据、校验器新增检查。
> 本文件在 `Docs_LYS/`，不改动仓库根目录原有文档。

## 1. 做了什么

`ADVENTURE_DESIGN.md` 第 5 节列了四种开箱谜题，此前只有「规则开箱（放对小马自动弹开）」能用。
这次把 6~10 关真正需要的两种补齐：

| 谜题 | 玩法 | 首次出现 |
|---|---|---|
| 符文顺序 | 盖子上方有一排颜色宝石，按「从左到右」的颜色顺序踩亮相同颜色的符文格；踩错顺序全部熄灭 | 第 6 关 |
| 线索石碑 | 场上有石碑，站上去按 `E` 读线索；读完埋藏点亮起一块金色标记，走过去按 `E` 挖出宝箱 | 第 9 关 |

两种谜题**所有视觉仍然由基础几何体拼成**（圆盘 + 菱形印记、石碑 + 浮空符印），
等第 3D 模型到货再按 `Docs_LYS/3D模型需求清单.md` 第 7 节的位置替换即可。

## 2. 符文宝箱

- **顺序提示**：盖子上方一字排开的小宝石，颜色从左到右 = 踩亮顺序；共 2~4 颗。
  用颜色而不是数字，是因为 760 cm 外的相机看不清小数字。
- **场上符文格**：一块圆盘 + 中间 45° 的菱形印记，未点亮时颜色压到 30% 亮度，
  点亮时恢复原色并略微抬起 1.2 cm，靠"抬一下 + 变亮"两个信号确认。
- **判定**：每进入一格就看它是不是下一个该踩的符文格
  - 是下一个 → 进度 +1
  - 是**还没轮到**的符文 → 全部熄灭，播错误音，HUD 提示「顺序错了，符文全部熄灭」
  - 是**已经亮过**的 → 忽略（走回头路不会把进度清掉）
- 进度满了自动解锁，宝箱弹开，再按 `E` 或踩上去领取。

## 3. 石碑宝箱

状态机：`未读碑 → 已读碑（埋藏点亮起）→ 已挖出（宝箱出现）→ 已领取`

- 石碑格按 `E`：显示 `clue.text`，并点亮埋藏点的金色标记；
- 埋藏格按 `E`：宝箱从土里冒出来（底座/盖子/宝石同时显示），播开箱音；
- 再按 `E` 或踩上去：领取奖励；
- 没读碑就按埋藏格：提示「这里埋着东西，但还不知道埋在哪——先去找石碑」。

**埋藏格与宝箱是同一格**（`cell == answer`），校验器会强制这一点，避免出现
「宝箱在一个地方、线索指向另一个地方」的错配。

## 4. 数据格式

```json
{"cell": [0, 0], "reward": "hint",
 "puzzle": {"type": "runes", "order": [[1, 0], [1, 1]]}}

{"cell": [2, 2], "reward": "hint",
 "puzzle": {"type": "stele",
            "clue": {"text": "宝藏埋在粉色草皮上，从上数第三条横带。", "cell": [3, 0]},
            "answer": [2, 2]}}
```

第 6~10 关现在的分配：

| 关 | 宝箱 | 说明 |
|---|---|---|
| 6 | 符文 ×2 | (1,0) → (1,1)，第一次出现 |
| 7 | 符文 ×3 | (1,0) → (0,3) → (1,1)，需要绕开中间的符文 |
| 8 | 符文 ×4 | (2,0) → (1,0) → (2,2) → (1,3) |
| 9 | 石碑 | 石碑在 (3,0)，宝箱埋在 (2,2) 粉区第三行 |
| 10 | 符文 ×3 + 石碑 | 两个宝箱同场，其中一个奖励换成苹果 |

## 5. 校验器新增的三道检查

`Tools/validate_adventure.py` 现在会拦住三类**以前看不出来**的错误：

1. **符文顺序不可完成**（`runes_solvable`）
   除了可达性，还要求在「踩到还没轮到的符文就全灭」的规则下真能依次踩完。
   BFS 的状态是 `(格子, 已点亮进度)`。
   > 这条检查上线当天就抓到一个真 bug：第 8 关最初把 (1,0) 排在第一，
   > 但 (1,0) 唯一入口是 (2,0)——而 (2,0) 是第二个符文，玩家永远开不了箱。
   > 顺序已改为 (2,0) 先踩。

2. **石碑答案与宝箱不同格**：`puzzle.answer` 必须等于 `chests[i].cell`。

3. **符文/石碑与障碍、宝箱、道具、正解格冲突**：
   - 符文格不能压在障碍/宝箱/道具上（和正解格的冲突沿用原有检查）；
   - 石碑不能立在正解格上（那一格要放小马）；
   - 符文格、石碑格都必须从起点走得到。

另外 `--level N` 的棋盘预览新增两个符号：`r` 符文格、`T` 石碑格。

## 6. 撤销与存档

- `SaveState/LoadState` 从 2 字节扩到 5 字节：`已解锁 / 已领取 / 符文进度 / 已读碑 / 已挖出`，
  所以按 `Z` 撤销时符文进度和石碑状态都会一起回退。
- **进行中存档仍然只存 `ActiveCells/HintsUsed/WrongAttempts/Lives`**，
  机关状态没有进 `UXiaomaSaveGame`。这是 `ADVENTURE_DESIGN.md` 里 `LevelRevision 5`
  要解决的事，本次没有动——中途退出再进来，符文进度会归零（但已经拿到的提示星不会丢）。

## 8. 一个环境问题（仅本机工具链，不影响工程）

本次编译时，构建加速器（UBA）无法从 UBT 子进程启动 `cl.exe`/`link.exe`，
所有编译动作在 0.06 秒内以 exit code 1 结束且不打印任何错误。
用同一份 `.rsp` 手动调用 `cl.exe` 可以正常编译，说明**源码没问题，是进程启动被拦**。
最终用「手动逐个编译 + 手动链接 DLL」完成（`Binaries/Win64/UnrealEditor-XiaomaLogic.dll` 已更新）。
另外 UBT 的导入库动作本身有个 `/DEF` 空参数问题（`LNK1146`），
`UnrealEditor-XiaomaLogic.lib` 一直没生成——本工程只有一个模块，不需要这个库。
在正常环境里直接 `Build.bat` 应该一切照旧。
